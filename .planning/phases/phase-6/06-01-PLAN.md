# Plan 06-01: Native Firmware Management Entity

## Goal

Implement the Home Assistant `update` entity to surface available Meraki firmware versions and allow users to trigger upgrades directly from the HA UI.

## Context

Meraki devices frequently receive cloud-managed firmware updates. Surfacing these in HA allows for better visibility and the ability to schedule or trigger updates alongside other smart home maintenance tasks.

## Tasks

### 1. Data Fetching

- Update `DataFetchManager` to include `get_organization_firmware_upgrades` in the slow poll cycle.
- Ensure firmware upgrade data is correctly mapped to individual devices in the model.

### 2. Update Platform

- Create `custom_components/meraki_ha/update.py`.
- Implement `MerakiUpdateEntity` inheriting from `UpdateEntity`.
- Map `current_version`, `latest_version`, and `release_notes` from the Meraki data model.
- Implement `async_install` to trigger the Meraki firmware upgrade API.

### 3. Discovery

- Register the `update` platform in `manifest.json` (if not already present).
- Update `UniversalDiscoveryHandler` to instantiate update entities for all devices.

## Verification

- Verify that update entities appear for devices with pending upgrades.
- Mock an upgrade trigger and verify the API call parameters.
- Ensure the entity state reflects "Up to date" when no upgrades are available.

<success_criteria>

- Users can see and trigger firmware updates natively in the HA UI.
- Release notes (if available) are surfaced in the entity.
  </success_criteria>
